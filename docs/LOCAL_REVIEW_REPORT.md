## 主要问题与修复

| 问题 | 原因与风险 | 本轮处理 |
| --- | --- | --- |
| Gemini 429 分类失真 | 通用 quota 文案被直接认作额度耗尽，Google 错误数组中的 details 和等待信息未被完整解析 | 读取错误数组、quotaId、quotaValue 和 retryDelay；区分短期限流、日配额、零额度、计费问题 |
| 失败后重复消耗请求 | 全文分析没有逐块恢复，标题批量失败可能继续拆成单条调用 | 缓存每个成功分析块；失败阶段可继续；翻译在批量或单条遇到配额/鉴权问题时停止后续请求 |
| 页面操作触发无关工作 | 多个 tabs 会同时执行，预览和下载存在重复路径 | 三个独立导航页面只执行当前页面；导出改为显式准备后下载 |
| 全文证据可能遗漏 | 分章节字典可能覆盖同名章节，依赖章节时可能丢掉前言等文字 | 优先分段完整正文，重复章节合并，延续块带页码，图注独立进入证据 |
| 图解被裁短 | 图解后处理仍有 700 字符截断 | 保留完整模型图解，不人为截短 |
| 图片复核重复调用或过期 | 图片、裁剪、模型、证据变化缺少统一缓存判断 | 对确认图片及分析上下文建立复核缓存；修改图片字节会失效；仅成功结果可复用 |
| 上传与裁剪可能污染旧稿 | 重名 PDF 或图名覆盖；上传控件在每次重跑时重复应用换图 | PDF 存储名包含哈希；重传同一论文切换到新来源；裁图使用内容哈希命名；替换需明确点击应用 |
| 稿件与下载不同步 | 修改后可能仍下载旧缓存；同名论文可能冲突 | 根据论文稳定标识更新稿件；导出指纹包含稿件内容和图片字节；编辑保存后校验资源完整性 |

截图中的 `limit: 20` 和 `Please retry in ...` 只能证明服务端拒绝了请求，不能单独证明是每日额度耗尽。程序现在优先读取服务端完整 quotaId；日配额提示优先于短暂等待提示。真实账号额度仍需在供应商控制台核对。

代码无法增加账号配额。Gemini 的限制按项目计算，可分别涉及 RPM、TPM 和 RPD；同一项目换 API Key 不会增加额度。参考：[Google Gemini 官方配额说明](https://ai.google.dev/gemini-api/docs/rate-limits)。

## 界面与流程

1. **文献检索**：明确自然月（如 2026年2月），期刊按已有 2024 JIF 排序且默认未选；先检索和关键词筛选，再主动翻译标题。
2. **论文分析**：导入区集中处理 PDF、题录及全文下载；全文分析显示已完成块数；首页截图可预览；图表选择、裁剪、替换与 Gemini 复核集中在同一工作区。
3. **成稿导出**：编辑保存、图文预览、准备下载、Word 下载集中展示；其他格式、公众号草稿和项目归档折叠收纳。

浅色画布、克制的青绿色操作强调、较紧凑的标题与边距用于降低视觉噪声。期刊表默认只显示选择、期刊名、影响因子及年度，保留底层 ISSN 等检索信息。

保留文献搜索、标题翻译、上传及开放全文、图表确认、Gemini 复核、成稿编辑、Word/HTML/Markdown/ZIP 与微信草稿；没有为简化页面而删除这些底层能力。正文模型可独立于 Gemini 视觉模型配置。

## 未验证及边界

- 按要求未使用真实 API Key：Gemini 实际读图能力、当前模型可用性、真实科研论文生成质量、费用及当前账号配额均未现场验证。
- 未向真实微信公众号上传素材或创建草稿，只验证 dry-run 与资源检查。
- Word 验证为文档结构、编辑和图片嵌入检查，未进行 Word 页面渲染对照；不宣称与附件像素级一致。
- 全文和视觉缓存只在 Streamlit 会话内恢复，页面刷新、会话中断或服务重启可能失去进度；不是持久化任务队列。
- 无人为字数上限不等于模型无上下文或输出限制；长文按证据分段。扫描件仍需可用 OCR，无法解析时不会假装全文分析完成。
- 目前每篇最多选择 4 个关键图表，超出会明确提示，不会静默丢掉选择。
- 本轮未重新核对或更新期刊影响因子，仅沿用既有数据与年度；检索数量仍有用户设置上限。
- 仓库中存在历史根目录副本和备份脚本，本轮未删除。实际网页入口为 `app.py`；后续可在确认依赖关系后单独清理，避免误删。
